## 额外发现与修复

在原实现上新增反例后，13 个反例均未被拒绝；不是根据代码推测：

- UNPARSED 来源被 EXPLICIT / INFERRED / UNKNOWN 三种规则引用。
- LOW 转录升级 EXPLICIT、遗漏 UNPARSED 范围、自身冲突、重复文档 / 片段覆盖索引。
- 虚报 caseCount、虚报 dimensionsCovered、重复 coverageMap、零用例无阻塞原因、声明规则却没有对应断言。

修复后全部拒绝，另补“零用例但有真实阻塞说明”的正例，保留正常阻塞路径。旧单测中两处不真实的覆盖表也修正：只生成一条规则的用例，其他规则明确列阻塞，不再假报全覆盖。

提示词增加来源质量、数字边界、缺省字段、覆盖对账和冲突双向引用说明；schema 定义顺序固定。用例生成明确所有业务文本都是数据，不能通过澄清文本授予工具权限。无效规则输入在模型调用前拒绝。

Kimi 文本结构化任务显式关闭 thinking，保留 120 秒请求 / 8192 输出 token 上限；JSON 不作正文替换、语义补写或自动补齐冲突。Schema 错误提供字段路径。提示词版本升级为 `agents-v2`，平台资产与调用记录同步保存。

## 真实模型结果与失败历史

最终固定提示词哈希见 `kimi-final.json`：

- 明确金额：严格大于 5000 元保留为 `gt / 500000 / fen`，保留自审批限制。
- 冲突：双方保留、来源齐全、互指并生成 CONFLICT 澄清。
- 缺失边界：UNKNOWN，不造金额数值，生成 MISSING_INFO。
- 部分解析：遗漏可见，UNPARSED 不作为规则来源。
- LOW 转录：不升级 EXPLICIT，要求人工核对。
- 用例生成：正式 APPROVED 阈值规则生成 5 条草稿，覆盖数量 / 维度 / 引用通过联合校验。

最终六次调用合计 **20036 token**（输入 + 输出），这是供应商返回用量，不是费用估算；不含开发阶段失败与先前试跑。完整开发试跑历史见 [trial-history.json](evidence/python-agents-2026-09-20/trial-history.json)。曾出现：文本超时、缺失边界输出不符 schema、冲突仅单向互指。系统全部拒绝，未修补为成功。停止批次的在途调用及缺响应的失败调用用量未知，不据此虚构总成本。

最终 6/6 是修订后单轮合成小样，不是首次成功率、生产精确率或重复稳定性统计。模型仍可能输出错误，公共校验继续强制执行；更多业务 / 文档规模、长文档分块、重复稳定性和隐藏缺陷检出仍待后续评测。

## 部署与剩余边界

- Python 服务必须启动并注入文本模型配置；worker 配置内部 URL / token，Python 使用同一 token。API 无需持有模型密钥。服务不自动加载 `.env`。
- 本地忽略的环境文件仅保存配置，不包含在 PR 中；此合并不会重启正在运行的服务。
- Docker 仍需 `--profile intelligence`；本次验证宿主进程路径，完整应用镜像构建未复验。
- mock 必须显式注册且不能回退真实调用；正式 Python mock 未注册时会失败，不再自动走旧 TS 模板。
- 自动分块、通用页面绑定、正式用例编辑 / 批准和完整项目执行闭环仍未完成。
- 上一轮产品 PRD / 原型修改保留本地，未混入本次合并。
