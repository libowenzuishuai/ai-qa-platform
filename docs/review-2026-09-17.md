# 阶段 1.1 独立复查与补充修复

基于 `47c8a90` 复查。修复范围保持在固定用例的真实浏览器执行闭环，没有接入模型或扩展阶段 2。

## 复查结论与代码修复

| 问题 | 本次修复 | 回归证据 |
|---|---|---|
| 事件取号和写入分离，较大序号可能先被 SSE 读取，较小序号随后永久漏掉；写入失败会留下空洞 | 行锁、取号、事件写入同事务提交；运行创建及生命周期终态与事件原子提交 | 真实 PostgreSQL 延迟事件写入、失败回滚反例 |
| 证据丢失后报告指标降级，详情/列表/报告头仍读缓存 PASS；断言未完成或计划删除后也可能 PASS | 三个接口复用报告复核；校验固定计划、必需断言唯一性与结果一致性；证据过期也视为失效 | 真实 Session 鉴权后的 HTTP 接口检查；断言 NOT_EVALUATED/REVIEW/FAIL、固定计划删除反例 |
| 已成功提交的幂等请求，会因后来观察文件过期而被拒绝 | 先校验请求指纹并返回已有运行，再校验新运行的资产 | 删除观察证据后重放同键请求 |
| 观察文件只检查存在，内容损坏或排队后删除仍能进入浏览器执行 | 创建时及执行前复核项目、类型、期限、校验和；登记哈希必须与计划 JSON 一致 | 内容篡改、新运行拒绝；排队后删除、worker 在任何步骤前 BLOCKED |
| 取消收尾在 CAS 成功前改 attempt；晚返回的 worker 可能覆盖收尾结果 | 取消状态与 attempt 同事务；worker 完成 attempt 时先锁定并复核运行状态；对账 CAS 同时检查心跳时限 | 过期取消调用不能修改运行中的 attempt；原取消/重复投递场景保持 |
| 登录页上业务元素缺失时 notExists 假通过；非超时异常被吞掉 | 缺失业务目标先检测登录态；明确区分正常等待超时和页面/浏览器故障 | 真实 Chromium 登录页反例 |
| 总预算仅在动作边界/轮询检查，goto 挂起可以超时；夹具不受 run 截止时间约束 | 浏览器硬截止定时器及剩余时间约束；写操作中止保留 UNCERTAIN_SIDE_EFFECT；夹具遵守 run 截止时间 | 1 秒预算下挂起导航及时中止；原提交挂起与 10 秒预算场景保持 |
| CONNECT 隧道未被 closeAllConnections 关闭，代理退出可能挂住 | 跟踪并关闭客户端/上游 socket，复用 socket 不重复登记监听器；修正 IPv6 CONNECT 解析 | 真实 TCP CONNECT 长连接退出反例 |
| 观察失败时清理的是外层另生成的 namespace；观察文件路径被多次种子观察复用 | 调用前生成 UUID namespace，传入浏览器并用于 finally 清理及证据路径；浏览器启动失败也释放代理 | 真实浏览器创建订单后故意观察失败，实际 namespace 与清理 namespace 一致 |
| 根测试命令因 run-events 包无测试而失败 | 补充 Redis URL 测试，拒绝非法数据库号，修正 IPv6 主机解析 | 密码转义、TLS、db、IPv6 三项回归 |

## 验收脚本修正

1. 固定端口被占用时，旧脚本会把其他服务的健康响应当成自己的启动成功。本次实测出现 API 端口占用。改成动态端口并检查本次子进程状态；只清理本次进程组与临时资源。
2. 原“发布 v2”夹具把登记哈希改成全 `b`，与计划实际内容不一致，污染后续场景。改为发布**合法的新版本**，以不同版本 ID 验证旧运行仍执行 v1；产品校验没有放宽，额外加入错误登记哈希拒绝测试。
3. 取消对账场景保持队列暂停直到出现终态，排除队列消费者代为收尾的可能。它是数据库状态故障注入，并非杀进程实验。
