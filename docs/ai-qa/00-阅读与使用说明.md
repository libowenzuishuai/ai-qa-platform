# AI 测试人员开发资料包

版本：v0.1 · 日期：2026-09-16 · 状态：待试点验证的开发基线

## 文件

1. **01-项目评审.md**：投入建议、原方案问题、技术取舍、风险与验证条件。
2. **02-产品需求文档-PRD.md**：产品边界、业务流程、功能验收、数据与接口契约、执行机制、实施阶段。
3. **03-GLM开发提示词.md**：开发总指令、分阶段任务、运行时智能体提示词、独立验收提示词。

## 怎样交给 GLM 开发

1. 在支持读写项目文件、终端和浏览器的 AI 编程工具里使用 GLM。普通网页聊天可以协助设计和生成代码，但不能据此认为已经真实创建项目、运行测试或操作浏览器。
2. 把本目录放入新项目的 `docs/ai-qa/`。如在现有项目开发，先让 GLM 阅读项目约定并保留已有结构。
3. 先发送 `03-GLM开发提示词.md` 中的“开发总指令”，随后发送“阶段 0”。阶段验收通过后依次发送后续阶段任务。
4. 不要仅发送一句“按 PRD 做完”。每个阶段都有产物、真实验证方法和完成条件。
5. 首次开发可用明确标记的离线模型适配器验证工程逻辑；交付真实智能体前，必须配置真实模型 API，并完成 real 模式验收。不能把离线演示当作真实模型效果。
6. API 密钥通过本地环境变量或应用的服务端凭据管理配置，不要贴入提示词、代码、报告或 Git。

## 模型角色

- **开发模型**：在你的 AI 编程工具中编写这套产品的 GLM。
- **运行时文本模型**：产品上线后，用于阅读需求、生成用例、分析异常。
- **运行时视觉模型**：产品上线后，用于读取原型图片或操作页面截图。

三者可以来自同一家供应商，但功能、权限和计费相互独立。不能假设购买了某个编程工具套餐，就自动拥有产品运行时的 API 调用额度。

模型名称、基础地址和能力参数全部配置化。文本模型不能直接接收图片；视觉接口失败不能用文本模型“猜图”。开发前按账号实际可用模型和官方文档做连通性验证。

## 使用边界

本资料包是项目评审与开发规格，不是已实现的软件，也不代表已完成模型效果实测。PRD 内的性能、成功率和周期均为计划或验收目标。第一版默认单组织私有部署、多个项目、Web/Chromium、测试环境。

长期目标是承担测试岗位的主要重复工作；试点期需要产品负责人处理业务歧义并评估缺陷有效性。
