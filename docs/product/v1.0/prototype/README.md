# AI QA 1.0 · 第二版产品原型

2026-09-20。配套 [产品战略](../PRODUCT-STRATEGY.md) 与 [PRD](../PRD.md)。独立静态原型，**不是已经接入后端的新平台**。

## 打开

直接打开本目录 `index.html`，或从仓库根目录运行：

```sh
python3 -m http.server 7840 --bind 127.0.0.1 --directory docs/product/v1.0
```

浏览器访问 `http://127.0.0.1:7840/prototype/#overview`。只服务设计目录，不暴露整个仓库。

## 信息架构

| 页面 | 重点 |
|---|---|
| 工作台 | 多项目交付、优先处理事项、四类目标入口 |
| 项目空间 | Git / 已有环境 / 自托管执行器三种接入形态 |
| 产品上下文 | 一次发现仓库资料、来源用途、业务冲突与决策 |
| 测试任务 | 发布验收、变更回归、项目体检、缺陷复测；目标与预算 |
| 执行中心 | 浏览器 / API / 已有测试的编排设计、进度、取消 |
| 交付评估 | 期望与实际、来源与证据、未完成项、复测草稿、独立交付决定 |
| 能力与集成 | 已实现 / 1.0 目标 / 后续能力；Harness 节点协议 |

旧 `#runs` 等入口仍映射到新版页面。

## 完整体验路径

1. 工作台 → 接入项目 → 填 GitHub 地址 → 发现项目资料（固定模拟数据）→ 选择资料纳入上下文。
2. 产品上下文 → 确认退款窗口冲突 → 选择适用来源并填写理由。
3. 测试任务 → 填写验收目标 → 生成示例方案 → 查看范围、预算和阻塞项 → 确认开始。
4. 执行中心 → 查看多能力模拟进度 → 完成后打开本次交付评估。
5. 评估 → 查看重复退款证据、复现步骤 → 创建复测草稿；记录交付决定或导出带模拟标识的 JSON。
6. 可另试：执行中取消、关闭某项执行能力、仅做项目体检、运行后修改上下文。缺口不转为通过，既有运行保留原始快照。

## 原型范围

- 完整样例采用订阅 SaaS；零售和 API 项目卡展示通用信息架构，不冒充三个已接入项目。
- 数据只在内存；刷新或“重置”恢复初始状态。本原型不提供完整历史存储。
- Git 发现不访问用户填写的仓库，明确展示固定示例；选择本地文件只显示文件名，不读取或上传。
- 生成与执行都是本地模拟；API / 既有代码测试 / 自托管运行器为规划能力，能力页区分实现状态。
- 默认业务评估：22 项，19 通过、1 失败、1 阻塞、1 未执行；通过率 86.4%，执行率 90.9%。取消或关闭能力时保留未执行缺口。
- 体检通过不代表业务通过。构建未核验始终可见。记录接受风险的决定，不改变 FAIL。
- 新复测仅建立目标草稿，尚未提供新构建选择和完整复测历史；正式产品要求在 PRD 中说明。
- 没有连接凭据库、Git、模型、真实执行器或问题系统，也不会部署任何用户项目。
- 当前正式工作台仍为 `apps/web` 的 Fastify SSR 实现。
