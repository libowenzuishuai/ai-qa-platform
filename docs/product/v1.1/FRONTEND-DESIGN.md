# 前端设计与实现交接

2026-09-20 · 本轮升级真实 SSR 前端的共享外观与工作台，保留现有路由、表单提交和 API。预览使用相同组件。

## 1. 风格

面向专业测试团队的工作空间：清晰、克制，有足够的信息密度。以任务进展、待处理问题和执行证据为中心，避免装饰性“AI 大脑”、虚假实时动画和无依据的通过率。

| 元素 | 约定 |
|---|---|
| 主色 | 深松绿 `#112e30` 导航；主动作 `#167568` |
| 背景 | 灰白 `#f5f7f6`，白色内容卡，浅绿重点区域 |
| 文字 | 主文 `#182c31`，辅助 `#65767b`；系统中文字体，无外部字体请求 |
| 风险 | 琥珀色待处理，红色失败；必须同时提供文字状态 |
| 布局 | 桌面固定 226px 侧栏、工作区自适应；低于 760px 转顶部横向导航 |
| 排版 | 30px 页面标题、17px 区块标题、12–14px 正文、规律留白 |
| 动作 | 每个区域一个主要操作；不可用时解释原因；提交后提供结果 |
| 无障碍 | 可见焦点、语义导航和当前页、表单 label、图标不独自承载含义、尊重减少动画设置 |

## 2. 本次已改的真实页面

- 所有共享 layout 页面使用新侧栏、顶栏、卡片、表格、表单、状态标签与窄屏样式。
- 七个项目页面用侧栏切换，移除原来的顶部文字链接堆叠。
- 工作台：标题与创建入口 → 验收入口 → 四项实际记录指标 → 接入进度与待处理项 → 最近运行与证据入口。
- 项目列表：项目卡片、人员角色、创建入口；隐藏不必要的内部 ID。
- 用例编辑：沿用完整版本表单，套用统一样式；保存动作固定在滚动视口底部附近，实际仍创建新草稿。
- 登录页：统一品牌和输入样式，不变更认证协议。

本轮工作台数字来自 API 返回的真实记录，列表有数量上限，页面明确注明统计范围。后续全量统计应在授权项目聚合 API 完成，不能用前端截断数组假装全量。

## 3. GLM 接着实现的页面结构

### 项目接入与准备

第一屏只输入项目名/仓库/网址。发现结果用“已有资料、已知服务、已有测试、缺少条件”呈现；账号与部署设置按需展开。每个角色一张卡：账号引用、登录流程、最近检查、有效期、缺口。测试数据页面显示创建/回收方式与资源，不要求手写 JSON。

### 产品上下文

左列资料目录，中间原文，右列规则/冲突。点击规则高亮精确来源；低质量内容不假装精确。变更视图显示新旧版本和受影响资产，提供“确认仍适用/创建修订/需要澄清”，不把新资料直接覆盖旧运行。

### 测试任务

列表默认按状态分组；新建依次确认目标、范围、环境、预算。详情区分业务用例和工程检查。右侧固定显示本次范围、依据、准备缺口与下一动作。自由描述目标尚未接编排服务前，不提供假装能自动执行的聊天框。

### 执行中心

左侧用例/节点列表，中间行动时间线，右侧实际截图/请求证据。显示当前阶段、已用预算、等待原因与处理人。取消、人工确认、恢复入口由真实状态决定。进度依据已记录节点，不能依据时间虚构百分比。

### 交付评估

顶部先给通过/失败/未完成与范围；下方按“必须处理、尚未验证、已验证”展开。缺陷详情提供期望/实际/来源/证据/原标准复测。代码检查结果单列，不能用它冲淡业务失败。

### 能力与集成

浏览器/API/代码运行器按真实连接和支持范围展示。组合模板首版用节点列表和表单，展示输入、输出、权限、版本、预算及清理责任；无执行引擎前标记设计中，不提供虚假的发布成功。

## 4. 预览

本地服务：`python3 -m http.server 7841 --bind 127.0.0.1 --directory docs/product/v1.1`

- `http://127.0.0.1:7841/preview/`：工作台。
- `http://127.0.0.1:7841/preview/case.html`：真实用例编辑组件的示例渲染。
- `http://127.0.0.1:7841/preview/capabilities.html`：能力组合的规划设计。

所有预览页面明确标记“设计预览 · 示例数据”。提交操作只显示预览提示；不会向平台、模型或目标项目发送请求。真实产品路由仍是 `/space/:projectId`、`/cases/:id` 等。

重新生成：`apps/web/node_modules/.bin/tsx tools/render-product-preview.ts`。输出 HTML 是设计快照，不手工修改生成文件。改共享渲染组件后再生成。
