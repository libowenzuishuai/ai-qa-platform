# 2.0 界面、信息架构与交互规格

> 新设计，非现有界面承诺。面向普通用户的页面讲任务与结果，内部表名、队列名和原始JSON放到高级详情。

## 1. 体验目标

用户第一次打开产品，能够回答：我能让它做什么？需要给什么？现在卡在哪里？结果是否可信？下一次能否直接复用？

视觉方向：浅色工作区 + 深色导航，蓝绿作为进行/主操作色。错误、警告、成功分别有图标和文字，不只靠颜色。任务时间线、证据和关键动作优先于装饰性统计。GitHub采用深色品牌横幅，但操作台以可读性为主，不用不断动的终端文字冒充智能。

## 2. 导航

- **工作台**：最近任务、待我处理、真实结果摘要、开始新任务。
- **项目**：资料与标准、环境与账号、资源/构建、回归资产。
- **测试任务**：正在运行、历史结果、缺陷与复测。
- **智能体配置**：团队预设、组合设计器、工具/模型；普通用户默认使用已发布预设。
- **设置**：成员、权限、运行器、费用/证据保留；管理员功能按角色显示。

“项目接入”和“需求资料”统一在任务引导中；资料仍可在项目内单独维护。仓库包含PRD时直接发现并选择版本，不要求重复上传。

## 3. 页面清单

| 页面 | 首屏必须看到 | 核心操作 | 不应出现 |
|---|---|---|---|
| 首页 | 最近结果、待办、可用环境、开始任务 | 新任务/继续待办/复测 | 空数据时假的完成率 |
| 任务创建 | 目标、资产输入、支持提示 | 粘贴仓库/网址/上传 | 强制填写内部ID |
| 接入分析 | 发现的资料/服务/版本与缺口 | 选权威资料、测试服务 | 自动认为README就是PRD |
| 计划确认 | 六维覆盖、未覆盖、动作范围、预算 | 批准/调整/澄清 | 100条重复用例冒充全面 |
| 准备中心 | 每角色登录、环境、数据和有效期 | 检查/人工认证/重试 | 密码进入聊天记录 |
| 实时控制台 | 当前步骤、页面证据、进展、成本、状态 | 暂停/接管/取消 | 无依据的“思考中”长时间占屏 |
| 缺陷详情 | 标准/实际、复现、首败、构建 | 确认/驳回/复测 | 把猜测根因写成事实 |
| 结果报告 | 通过/失败/阻塞/未测分母、结论限制 | 导出/发布决策 | 一个绿色大勾掩盖未测 |
| 组合设计器 | 配置版本、能力图、校验、试跑 | 组装/发布/回滚 | 宣称任意工具已兼容 |
| 效果评测 | 冻结范围、样本/首轮/重复、费用 | 比较版本/看原始结果 | 无分母百分比 |

## 4. 新任务流程

### 第一步：描述目标与输入

主输入示例：“验收这次采购审批改动，重点检查阈值和越权。”下方三个同级入口：仓库、测试网址、资料。允许先给一个；系统解释还缺什么。凭据通过账号配置入口输入或引用，不进入目标文本。

开始后显示只读发现进度、已识别和未识别的内容。仓库授权失败提供重新授权入口；不能自动切换另一个用户凭据。Git-only任务先给可做工程检查和业务依据缺口。

### 第二步：确认依据与范围

每份资料卡显示版本、更新时间、出处、解析质量及权威状态；冲突并排展示，选择“待澄清”也能保存。覆盖地图按规则和六类检查展开，显示已设计/阻塞/不适用，支持查看具体来源。

“允许行为”用普通语言列明：使用哪些角色、可以创建哪些测试资源、禁止哪些操作、预算上限、清理方式。一次批准这个范围，范围内不反复弹窗。

### 第三步：准备与启动

列出必须解决的缺口与可并行做的事情。账号需要验证码时进入受控浏览器接管，会话凭据不导出；成功后返回准备状态。无法核对构建时明确标“已声明，未验证”。

开始按钮仅在必需门满足后启用；可保存草稿或执行不依赖缺口的明确子任务。不能默认跳过缺资料用例再给全项目PASS。

## 5. 实时控制台布局

```text
项目 / 本次目标                   运行中  已用预算/上限   暂停  取消
固定构建 · 标准版本 · 角色 · 自主范围
┌────────────────┬─────────────────────────┬────────────────┐
│ 任务与覆盖      │ 当前页面 / 当前证据      │ 当前动作与依据 │
│ 准备完成        │ 截图时间、角色、来源     │ 选择哪个工具   │
│ 主管审批 进行中 │ 可打开DOM/网络摘要        │ 为什么这样做   │
│ 持久化 待执行   │ 首败与当前结果可切换      │ 预算与下一步   │
├────────────────┴─────────────────────────┴────────────────┤
│ 时间线：观察 → 操作 → 效果 → 判定 → 调整 / 待办            │
└───────────────────────────────────────────────────────────┘
```

默认只展示简短理由和事实，无需暴露模型内部思维链。展开后可查工具调用、拒绝原因、模型版本、原始输出（按权限）。未配置视觉时如实显示能力缺口，不展示假的实时视频。

等待人工时固定展示一个最小待办：缺什么、为何必须、补充后从哪里继续。重启或刷新不丢待办。暂停与取消分开：暂停停止新派发并保存，取消停止后续并进入资源核对/清理；已在外部发生的动作不能承诺撤销。

## 6. 缺陷卡与复测

卡片至少包含：违反的批准规则、expected/actual、角色与数据前提、首败证据、最小复现、构建和时间、确认状态。根因放独立区，列支持/反对证据及UNKNOWN。

确认/驳回填写简短原因，保留原始候选。复测默认沿用原Oracle；用户要改预期时跳转“需求变更”，不得在缺陷卡上改expected使其通过。

报告上方并列“业务结果”和“执行完整性”。发布决策可接受风险，但原FAIL仍在。导出不嵌入受限证据直链，授权用户从平台查看。

## 7. 组合设计器

默认从“发布验收”“探索业务”“补充代码测试”三个预设进入；不是空画布考用户懂多少工具。每个预设显示支持环境、角色、预计动作范围与最近兼容验证。

能力左栏、画布居中、节点配置右栏、校验/试跑下栏。节点可重复，可明确子流程和有界循环。表单模式拥有相同功能，与画布共享AST；拖拽只是编辑方式，不是另一套执行语义。

配置字段有类型、来源绑定、默认值及权限说明。表达式提供选择器，不要求用户写JavaScript。缺失插件、Schema不兼容、循环无上限必须阻止发布并定位具体节点。

安装/升级插件在管理员页面，普通用户只见已批准目录。模型下拉只展示已验证该用途的模型；Jev只出现在决策配置，不混入代码生成模型。

## 8. 状态、可访问性与适配

所有数据区必须实现 loading/empty/ready/error/forbidden/stale，区分“没有结果”和“未配置/获取失败”。网络断开显示最后更新时间，恢复SSE时从序号续传，不重复添加事件。

1440、1024、390宽度均可查看任务、证据、待办和报告；复杂画布在手机改成节点列表编辑，不强塞缩小图。键盘操作、焦点、对比度、屏幕阅读器标签和reduced-motion都要验收。

时间、金额、单位、时区明确；敏感字段默认隐藏。指标无数据显示“尚未评测”，不显示0%暗示测试失败，也不显示100%暗示成功。

## 9. 可用性验收

邀请至少5名未参与开发的目标用户，完成：从Git+PRD+网址创建任务、识别阻塞、接管认证、理解缺陷证据、沿原标准复测、修改预设。记录完成/中断/求助与耗时，不提示内部结构。

候选门：5人中至少4人无开发人员引导完成前五项；技术用户另测SDK安装与模板发布。失败点进入问题清单修复再测，不用“用户不懂技术”解释信息设计缺陷。

本规格指导下一轮真正前端原型与实现；当前GitHub展示的是1.0真实截图，不能用新设计图冒充已运行功能。
