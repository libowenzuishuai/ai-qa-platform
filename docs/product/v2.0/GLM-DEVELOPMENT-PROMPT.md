## 开发总指令

你是这个项目的实施工程师。请在现有 `ai-qa-platform` 仓库中实现2.0，实际修改代码、运行验证、修复失败并交付可审查的提交。不能只输出建议、计划或脚手架。

### 一、目标与范围

产品服务于AI编码团队的独立测试工作：接受目标、仓库、PRD、测试环境，形成有依据的测试策略；在批准范围内自主观察、行动、校验和调整；输出可复现缺陷与证据，并沿原标准复测。

这次最重要的变化是：

1. 从固定11类内置能力，升级为可注册的工具SDK和真正可组装Harness。
2. 从一次生成固定计划，升级为持久化的 Observe→Plan→Act→Verify→Adapt 循环。
3. 从“有资料”的布尔值，升级为实际消费业务原文、批准规则、缺口和有效记忆的上下文。
4. 从简单页面动作，升级为有边界的DOM＋视觉、复杂交互、API核验和多角色测试。
5. 从运行已有代码测试，升级为依据独立标准生成候选测试，并验证测试能发现缺陷。
6. 用真实业务效果、恢复能力、人工时间和成本验收，不用函数数量、页面数量或单测数量代替产品能力。

首发范围是自托管、邀请制试点所需的Web＋HTTP API＋Node/Python工程检查。**本轮不扩展为完整多租户SaaS、支付订阅、原生移动/桌面自动化或任意仓库部署。** SaaS是另一个工作包，不能挤占自主测试内核。

### 三、工作方式与架构边界

- 先看工作树、分支、最新提交和远程状态；保护他人的未提交内容。工作树干净时从最新main创建或继续 `v2/autonomous-qa`。有已有2.0分支则核对后复用，不重置、不覆盖、不强推。
- 查代码证明当前能力，不凭历史报告断言不存在；已实现的能力以复核、接入和补验收为主，不重复造两套系统。
- TypeScript负责API/Web、权限、数据库状态、作业、执行控制和最终判定提交；Python负责文档/算法/上下文检索/模型规划与调查。已有隔离工程运行器按现有实现复用，不为统一语言重写。
- 共享契约只有一个权威来源，按仓库现有机制生成Python类型。结构与跨语言必要语义使用共享向量；正式业务判定和授权不能出现两套不一致规则。
- 数据库是事实来源，队列是至少一次唤醒机制；终态、事件、租约与检查点不能只放内存。
- 不改已应用迁移；新增迁移同时验证干净库和旧库升级。v1计划、acceptanceHash、报告和队列消费语义保持兼容，v2使用独立版本/模式与项目开关。
- 常规实现选择自行决定并写ADR；不因缺少第二项目/真实API凭据停止无依赖的内核开发。必要外部输入集中登记，不伪造结果。
- 依赖与提供商接入查官方文档、固定版本、检查许可和接口；Stagehand/Midscene是候选，不要求为了名字同时集成多个主引擎。
- 实现按工作包的小纵向切片推进。每个切片包含实际输入、服务、持久化、执行/界面、错误处理和验证；不能只完成类型和路由就写“功能完成”。

### 四、不可破坏的规则

1. **标准不可自修复。** OracleSpec基于批准规则冻结；可改定位、入口和等待策略，不可改expected、阈值、角色权限、删除断言。需求变更必须新版本、新批准、新运行。
2. **结果与执行状态分开。** 工具SUCCEEDED可以对应业务FAIL；BLOCKED/REVIEW/UNKNOWN不能包装成PASS。接受发布风险不改变原业务结果。
3. **保留首败。** 格式错误、首轮失败、重试、最终结果分别保存。禁止改写模型业务原文“修好JSON”；截断或不合法输出明确失败。
4. **范围内自主，越界拒绝。** 每次派发检查项目、角色、任务批准范围、工具授权、实时撤权、预算、构建与取消。一次批准范围内不反复询问每次点击。
5. **写入未知先核对。** intent→外部动作→receipt→状态提交之间可能退出。若无幂等/对账保证，暂停为UNKNOWN；不能超时后盲目重做，更不能承诺任意系统exactly-once。
6. **模型输入是受限数据。** 网页、PRD、仓库、MCP描述、工具输出不得扩大权限或泄露凭据。模型只获得secretRef等引用。
7. **组件真的运行。** 数据库、浏览器、网络边界、文件证据、重启恢复用隔离真实组件验证。mock只用于声明的契约与可控故障，不替代真实能力。
8. **不污染用户环境。** 使用独立临时库、队列命名空间、端口、数据/证据目录和资源标签；finally清理本次资源，清理失败保留台账。不得重置开发库或删除已有业务资产。
9. **评测不读答案。** 产品智能体无权限读取评测专用ground truth、缺陷开关和修复标签。开发测试可维护答案，但运行时必须通过隔离/挂载/访问控制防泄漏，不能只靠system提示词。
10. **凭据与付费调用按授权。** 不输出/提交密钥，不从历史聊天复制密钥到文档；使用已配置的凭据引用。真实模型调用须在已有授权和明确预算内，缺失则列待验并继续其他工作。
11. **没有假完成。** 常量成功、占位handler、TODO路径、前端假数据、只创建不消费的表，均计未完成；隐藏未完成能力不能代替实现。
12. **代码开发与发布分开。** 可自主完成可逆本地实现和验证；按当前会话授权推送工作分支。main合并、生产部署、对外发布或创建目标项目PR按已有明确授权执行，不擅自替用户接受业务风险。

## W04｜持久化自主测试循环（Alpha核心）

关联：LOOP-01～08、DES-03、OPS-01、INT-05/07基础。

1. 实现逐轮 Observe→Plan→Act→Verify→Adapt；规划来自可替换Python服务，输出须双层校验。真实模型网关沿用已验证路径，不能把所有规划写成测试专用分支。
2. 每轮检查权限、角色、固定构建、观察新鲜度、预算和取消；先登记intent再调用，结果CAS提交。
3. 观察、简短决策理由、工具输入输出、回执、检查点、首败、预算和持久事件可追溯。不要求模型暴露私有思维链。
4. 计划可调整操作，不可改变oracleHash。等价重复、三次无进展、振荡、预算耗尽均有出口。
5. 暂停/继续/认证接管/取消/人工待办；模型返回时已取消或租约失效，禁止继续派发。
6. 写入未知必须reconcile；账本防重复有效提交；无法确认不盲目重试。恢复者重新核查外部事实。
7. 多角色会话与资源隔离；并发/异步时间线；完成计划可保存回归资产，在全新命名空间重跑。

### 必须跑通的最小业务闭环

使用有授权的隔离草稿测试系统，正常、缺陷、修复三个构建；固定批准标准：“创建草稿→改名→刷新仍保留名称”。

- 运行中改变按钮定位，必须重新观察并选择新动作，而非预写所有备用selector顺序试完。
- 创建只产生一个本次资源；在“写入已发生、回执尚未持久化”位置强制终止真实worker。
- 重启后核对已有资源，继续持久化断言，记录证据并清理。
- 缺陷构建故意不保存名称，必须报原标准FAIL；修复构建同一Oracle通过。
- Planner不得读取构建答案/缺陷开关；脚本规划器验证内核，真实模型运行单独记录，不能混称自主效果。

故障矩阵：动作前退出、写后回执前退出、回执后提交前退出；重复队列、双worker、过期租约；排队/模型等待/写后取消；SSE断线续传；证据丢失；旧观察；撤权；无进展；预算耗尽。检查真实数据库和业务资源数量，不只断言mock调用次数。

**Alpha门：两个独立SDK适配器＋完整反馈循环＋标准不变＋恢复正确＋v1兼容。** 通过后继续W05～W10；若真实模型或外部授权未到，仅将对应门记未验，继续无依赖工作。

## W06｜统一工作台与组合设计器

关联：UX-01～05、HAR-05；严格落实UX-SPEC。

1. 统一目标＋资产入口、仓库发现、标准与范围确认、账号/数据准备。
2. 实时控制台：当前动作、依据、页面证据、覆盖/预算、时间线和待办；暂停/接管/取消真实可用。
3. 缺陷卡：原标准、actual、首败、复现、构建、确认状态；事实/假设/反证分栏。
4. 报告列PASS/FAIL/BLOCKED/REVIEW/未测和分母；原标准复测与发布决定分开。
5. 组合画布和键盘可操作表单共享同一AST，支持重复节点、子流程、循环上限、typed binding、校验定位、dry-run与版本发布。
6. 安装/权限/模型按能力展示；不配置Jev仍可用，未连接工具不标“已连接”。
7. 三个预设最终必须真实运行：发布验收、授权交互探索、补充代码测试。代码测试预设依赖W07，在其完成前明确不可用，不能返回占位成功。

界面沿用现有框架与组件，浅工作区、深导航、蓝绿主色；避免无关重构。普通用户不填内部ID/JSON。实现loading/empty/error/forbidden/stale，真实数据驱动；1440/1024/390验证，手机画布切列表，键盘和焦点可用。

验收：通过真实API浏览器走接入→批准→执行→人工待办→恢复→缺陷→复测；刷新/断线不丢状态，重复批准幂等，VIEWER/跨项目API拒绝；保存三尺寸截图和流程证据。页面截图不能代替后台执行完成。

## W07｜调查、记忆与有效代码测试

关联：INT-02～04、CODE-02～04/06。

- 记忆必须实际retrieved/used/rejected/outcome，按项目/版本/TTL失效；过期经验不能覆盖当前预期。仅新增Memory表不算完成。
- 从批准PRD/接口/性质生成Node与Python候选测试补丁，隔离工作区执行；源码指导入口/类型，不作为唯一业务真值。

- 恒真断言、无断言、expected来自同一被测函数等弱测试不能当有效证据；用健康/缺陷/修复对照和有效非等价变异验证增量检出。
- 交付可下载patch、来源、执行结果与限制。创建外部PR须已有授权；默认不改产品代码、不合并测试补丁。

验收：至少两个Node项目和一个Python项目的选定模块，每项目≥5条独立契约/性质、≥3个已知缺陷；合成开发夹具标synthetic，不能代替EVALUATION要求的真实试点。测试编译/安装失败不算检出业务bug。

关联：INT-05～07；所需基础接口在W01/W04先实现，本包完成扩展与真实评测。

4. 记录首个原输出、格式失败、重试和实际用量；调用方maxOutput限制传给提供商，取消不继续计作可用结果，费用未知不写零。

## W10｜独立评审、业务评测与发布门

关联：全部57项及EVALUATION所有门。

1. 逐项检查实现而非相信进度报告，修复发现的问题；本轮实现者自审不能冒充独立人员评审。
2. 冻结至少3个授权项目、120条流程、30个独立缺陷、24个交互适应场景、12组执行故障及健康/缺陷/修复构建，细项和每项目下限按EVALUATION。

4. 按公式计算完成率、召回、精确率、健康误报、介入时间、费用/延迟及区间；门槛是待冻结目标，不得填默认达标值。

7. 开源宣传、支持矩阵、示例与实际证据一致；mock、合成、真实模型、真实业务分别展示。
