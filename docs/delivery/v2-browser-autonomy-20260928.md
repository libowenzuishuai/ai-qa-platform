# 2.0 网站自主能力增量交付

日期：2026-09-28。基线 `ec6c71e`，开发分支 `v2/autonomous-qa`。

## 结论

本轮补通了受批准操作范围约束的网站自主执行链：真实页面观察 → Python 规划 → 授权动作 → 新观察 → 独立业务断言。它已经可以作为 Harness 中的节点运行，不再依赖合成草稿系统的专用 HTTP 接口。

**仍是开发预览，不是完整 2.0 发布。** 本轮没有调用付费模型，没有把合成项目的通过率当作真实产品效果，没有合并 main。下面分别说明代码支持、实测范围和未完成部分。

## 已接通的功能

### 1. 网站自主执行与角色

- `platform.browser-agent@1.0.0`：注册式本地能力，受持久化图宿主管理；多个节点使用独立浏览器实例与不透明实例引用，读取节点不能借用别的运行。
- 每轮重新获取可见元素、名称、角色、标签页、iframe、位置和截图。模型只能返回本轮观察 ID、已批准操作 ID 和实际元素引用。
- 动作包括填写、点击、选择、导航、刷新、切换标签页、短暂等待。动作参数和依赖由已发布组合冻结，规划器不能替换。
- Python `semantic-v1` 只依据前置条件和唯一元素匹配，不调用模型；`model-v1` 接模型通道，根据当前观察提议动作。
- 每个业务角色独立 BrowserContext、cookie 和标签页。复用准备中心的登录配置及凭据引用；密码不进入操作规划。登录工具调用计入预算。
- 浏览器请求仍经过连接层代理；非读取请求需要批准的 method、pathname 和 origin。省略 origin 只授权当前角色起始站点，不会因为另一个域名允许读取而自动允许向它提交数据。
- 原生 alert/confirm/prompt 采用逐操作批准的类型、完整文案和接受/取消策略；意图入库后才处理，重复或文案变化时停止。
- 新鲜度和唯一性检查拒绝过期/重复/伪造引用；验证码和 MFA 不自动绕过。
- 动作意图、回执、观察、截图、规划输入/输出落入现有证据库。写入状态不确定则等待核对，不自动重复。
- 浏览器进程丢失后不能复用其 cookie/页面状态。已完成写节点的历史回执仍保留，但系统不会为了恢复页面而重做写操作。

### 2. 视觉及独立判定

- 截图经过输入框遮盖，包含 iframe 中的输入框；文件哈希验证后才供视觉通道使用。
- 模型视觉规划使用现有 Vision 协议；需要在配置中单独授权。
- 坐标必须在本轮截图、当前标签页、已批准目标元素范围内；截图改变或坐标越界则拒绝。执行前仍检查元素可见、稳定、未被遮挡。
- `platform.browser-read@1.0.0` 从同一浏览器实例的指定角色重新读取页面。支持测试标识、字段标签、可见文本和可访问性角色；读取表单字段时获取真实 value。
- 规划器的 done、工具成功回执和视觉猜测都不直接构成业务 PASS。断言使用冻结 Oracle；允许角色必须与真实读取角色一致。

### 3. 策略组装、记忆与回放

- 网站自主节点可与既有 HTTP、MCP、远程 Python 工具、子流程和图策略组合。
- Profile 固定能力安装、规划策略、视觉开关、验证策略和经验策略。未实现的策略不能发布为有效配置。
- 模型调用与 token 先预留预算，失败/中断不返还成“没调用”。金额预算在没有可信价格配置时明确拒绝，不能拿 token 上限冒充金额上限。
- `approved-memory-v1` 只在模型规划中使用有效项目经验；来源、环境、业务标准、TTL 校验后记录 used/rejected 和请求证据。收益仍为 unknown，不伪造效果。
- 运行页提供零外部调用的演练入口：核验发布图、配置与参数，不创建执行会话；依赖真实输出的条件保留无法解析状态，不据此判断业务通过。
- 新增持久记录回放 API 和页面按钮：按原输入哈希与原始回执重放图计算，保留失败/重试，缺证据即失败，不访问目标或模型。回放包含原始工具输出，限制为 LEAD 及以上。纯图内核已移到共享包，API 的独立构建不再依赖 worker 源码。

### 4. 自动证据调查

- 业务断言失败后自动生成基于证据的初步假设。
- 关联网络错误、认证拒绝、写入回执和后续读取；支持证据、反对证据分栏。
- 缺陷详情页可以重新分析当前证据。文件缺失、跨项目或哈希不符时拒绝调查。
- 5xx 只能支持“服务或依赖故障方向”，不能直接宣称定位到某个代码函数；无法区分时保留 open/unknown。
- 原来的独立复现、健康/缺陷/修复对照和首次失败记录继续保留。

### 5. 效果评测记账

- 管理员冻结带授权证据和独立真值来源的样本集合；合成/授权真实项目分开标记。
- 创建运行与样本登记在同一事务中完成，提交后才入队；既有排队运行的补登记通过行锁与 worker 认领互斥。
- 运行必须在开始前登记，且匹配冻结的构建、Oracle、Profile。执行完再挑成功运行补登记会被拒绝。
- 每个冻结流程的第一次登记是主结果，补跑不能替换；未运行、阻塞、缺证据仍在分母。
- 对独立缺陷去重统计召回；完成率、健康误报率给出分子/分母和 Wilson 区间。
- 原始试验不可改写。展示时重新核验证据有效性，失效的证据不能继续支撑通过率。
- 评测页面可冻结样本、查看批次、带冻结流程发起运行、收录结束的运行，以及查看首次结果、分母和置信区间。授权材料和独立真值均须为本项目可校验证据；只有管理员可访问。
- 人工时间标为操作人声明；未计量费用保留 null。单项目批次不会自动升级为全产品发布通过。

## 产品入口

项目空间 → 智能测试 → **配置网站自主测试**。

1. 管理员点击“启用网站测试能力”，安装与授权仍走原有 API。
2. 填写角色、起始网址、允许写接口和操作范围；账号在准备中心配置。
3. 选择结果读取方式、规划策略和经验策略，保存为已发布组合。
4. 运行页选择环境、批准标准、构建和预算。将标准绑定到复核节点的 `text` 或 `visible`。
5. 会话详情查看判定与证据，缺陷页分析、独立复测，停止的组合可回放。

## 实测与限制

真实组件：PostgreSQL 临时库、Chromium、Python HTTP 服务、登录表单、独立角色 cookie、iframe、第二 HTTP 接收站、健康/缺陷/修复三构建。输入数据和目标业务均为合成夹具。

- 全量契约：310 通过。
- API：122 通过、2 项可选候选测试容器验收跳过；这两项上轮有记录，本轮未重跑。
- Python：411 通过；视觉管线使用显式替身验证图片校验和与输出边界，不证明真实视觉识别质量。
- V2 worker：最终全套 102 通过，覆盖原子评测登记、首次结果、弹窗、回放权限和演练零调用。
- 全仓类型检查通过；api/worker/web 构建通过；TS/Python 生成契约一致。
- 本轮没有重建四个生产镜像，不能沿用上轮镜像验收声称这些新代码已完成容器发布验收。

### 尚未完成，不能标为 VERIFIED

1. **开放式网站探索**：当前根据已批准操作目录规划，不是仅提供任意 URL 就能自己获得业务标准、写权限和全部操作范围。复杂表格、控件语义变化和长期异步任务需要进一步适配。
2. **完整复杂交互**：通用上传/下载及内容归属、真实 MFA 人工接管并继续原浏览器实例尚未接通。当前交互认证会明确阻塞。
3. **完整策略产品**：模型供应商/模型版本全路由、生产级单节点调试/故障注入界面、带真实输出替身的单节点演练及平台资源自动核对/清理仍有缺口。现有演练核验结构，不伪造真实输出。浏览器写入资源计数为保守预留，不能当作实际创建资源数量。
4. **深入根因与最小化**：自动分析已有证据已接通，但仓库代码 diff、服务日志关联、真实隔离重置下的有界复现最小化未完成。
5. **真实效果**：尚无本轮付费 Kimi 结果、三授权项目/120 流程/30 独立缺陷、两周试点、独立 QA 真值和人工基线，不能报告“达到替代测试人员的比例”。需要用户确认模型费用额度并提供授权试点资料。

上述均保留在 2.0 台账里。本轮是可运行增量，不能用“接口存在”或“合成测试全绿”替代完整 PRD 验收。

## 本轮实际发现并修复的问题

- 页面旧的 networkidle 状态可能早于本次点击触发的异步请求：改为按角色跟踪本次请求及结束后的静默窗口，真实夹具延迟 50ms 发请求，确认不会误拦截，也不会提前判完成。
- 原始回放结果可能包含受限输出：将回放权限从 VIEWER 收紧为 LEAD，并加入越权拒绝测试。
- 先运行后登记的评测存在竞态：增加创建运行时的原子登记，外部补登记对会话行加锁；真值及评测批次不进入 worker 请求。
- API 引用 worker 图内核导致独立编译失败：抽取纯共享图内核，由 worker 注入真实执行器，由 API 注入历史回执；分别构建验证。
- 中间全量验收曾出现异步请求误拦截和既有 web-observe 用例未通过，已保留日志并补诊断。修复后完整 V2 回归通过，不把失败记录从验收过程删除。
