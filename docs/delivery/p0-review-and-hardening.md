## 现在可以做什么

1. 管理员登记项目专属凭据引用，配置用户名/密码登录步骤和成功、失败、人工认证标识。UI 支持测试标识、标签、文字、控件类型与名称；原始密码不入表单或数据库。
2. 负责人启动可取消的真实登录检查。结果区分成功、凭据无效、缺变量、定位失败、不可达、超时、需要人工认证、取消和平台异常。
3. 注册受限 HTTP 数据准备方案。每次准备分配独立命名空间和资源 ID，查询、清理、清理失败、未知结果可在台账追踪；不会向第二接收站跟随重定向。
4. 用例选择该数据方案后，正式 Run 会在浏览器业务操作前准备数据，按用例清理策略收尾。自动清理失败时用例 BLOCKED、整体 INCOMPLETE；若已有业务失败，仍保留 FAIL 优先级。
5. 从已批准基线或需求资料创建固定模板工作流：解析 → 规则 → 规则审批 → 用例 → 用例审批 → 观察 → 计划建议/审批 → 准备检查 → 执行 → 评估。人工门核对已批准资产，模型不能自批。
6. 已解析资料复用原有来源片段；正在解析的资料等待已有作业，不重建来源 ID。已批准基线复用固定版本；环境变更则停止，不悄悄切换。
7. worker 自动推进工作流，不依赖浏览器页面维持。重启读取检查点；确认、重复投递、取消不能重放已执行业务。

“流程完成”表示处理步骤结束，业务是否通过由最后的报告判断。

## 数据方案接入协议

管理员登记准备、查询、清理三个相对路径。接口需实现以下协议，不能把任意业务集合接口直接当作清理接口。

- 准备请求为 POST/PUT，JSON 为 `{resourceId, namespace, parameters}`，必须使用平台分配的 resourceId 标识本次资源。
- 查询为 GET，例如 `/test-resources/{resourceId}`。准备返回成功后必须能查询到该资源。
- 清理为 DELETE，例如 `/test-resources/{resourceId}`。不允许集合清理路径、完整 URL、父目录或百分号编码路径。
- 只有在注册时明确声明 `allow404=true`，404 才表示已不存在。超时、重定向、不明确响应保留待核对/清理失败状态。
- 不确定创建禁止重放同一准备键；先 inspect，再清理已登记资源。人工清理策略保留资源供负责人处理。
- 清理有独立的最多 30 秒预算；取消业务不能继续业务动作，但可清理自己的资源。
- 环境地址变化后禁止对新环境清理旧资源；地址相同的账号配置版本变化不阻止核对旧资源。新准备仍要求注册环境版本匹配。

首版是上述专用测试接口协议，不包含任意脚本、数据库直连、任意 HTTP 鉴权插件或自动适配所有业务 API。

## 工作流预算口径

- 总时长包含等待人工批准；最长一天。
- 模型调用/Token 在创建子作业之前保守预留，未使用额度不回收。普通模型节点预留一次调用，文档节点最多预留 16 次视觉调用；超出本次额度明确停止。
- Python 网关每次实际请求前检查调用额度，并按序列化 UTF-8 字节和输出上限保守预留 Token；输出上限实际传给供应商。这是保守额度控制，不是精确计费报价。
- 模型真实 usage 继续记录在 ModelInvocation；页面将预留额度标为“预留”，不冒充已消费 Token 或费用。
- 工具额度包括子作业调度和为执行器保留的动作额度；清理使用独立有限预算。
- 没有无限重试：模型或写入失联保留失败/待核对。当前固定模板失败后检查原因并新建实例，不提供任意节点倒退或盲目重放。

## 验证方式

`pnpm test:p0` 使用真实 PostgreSQL 临时库、独立 Redis 容器、两个本地 HTTP 站点、Chromium、Python HTTP 服务及真实 worker 进程。测试数据不写入开发库，finally 清理临时库/容器/证据。

重点覆盖：

- 成功/错误密码/缺变量/MFA/定位失败/超时/过期/取消与越界凭据拦截。
- Redis 入队失败补投、过期执行不能回传成功、同参数并发只创建一次。
- 两个数据空间互不影响、清理失败保留、404 语义、跨插件拒绝、未知创建不重放。
- 解析调度检查点、人工等待检查点、Run 创建检查点的真实 SIGKILL 重启。
- **外部写入已经发生但 HTTP 响应前 SIGKILL**：台账转 unknown，重复准备被拒绝，核对后可清理。
- 真实基线到报告、数据插件进入真实 Run、清理失败不通过。
- 需求到报告完整链路：生产 Python 解析/管线/网关，三个真实批准门，真实观察与浏览器执行。模型供应商响应由本地协议模拟器提供，**不代表 Kimi 模型质量或 Dify 客户验收**。
- 实际 worker 自动扫描、BullMQ 消费并完成工作流，页面不轮询也能推进。
- 真实浏览器保存登录配置，查看准备中心与工作流；窄屏不横向溢出。

## 非破坏性升级

1. 使用本分支的新代码，执行 `pnpm --frozen-lockfile` 和 `pnpm --filter @ai-qa/api db:generate`。
2. 备份目标库并停止旧 worker，执行 `pnpm db:migrate`。新增迁移 `20260921090000_p0_hardening`，没有改写旧迁移、没有重置数据库。
3. 同时重启 API、web、worker 和 Python intelligence；模型预算头要求本次 Python 网关配套。
4. GLM 旧版没有保存完整环境/接口定义的登录或数据配置，必须在准备中心重新登记，不能推断成可执行配置。旧数据记录保留。
5. 如果新唯一索引发现旧重复工作流节点/资源，迁移会停止；先备份并逐项核对，不自动删除用户记录。
6. 修改账号或环境配置后重新检查登录；对应已绑定计划需要重新观察和批准。先完成准备配置，再创建正式工作流。
