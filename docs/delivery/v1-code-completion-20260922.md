1.0 支持范围内的代码、核心页面和本地组件验证已完成。正式发布仍有外部验收门：真实 GitHub App、完整批准 PRD 与第二真实业务项目/独立角色，以及新增长文档/目标规划的真实模型评测。当前是代码候选版，不把模拟服务、合成夹具或历史 Kimi 小样本等同于完整商业发布通过。

## 已形成的产品闭环

- **资料到标准**：Markdown/DOCX/PDF/图片解析；来源与质量标记；多文件快照/改动复核；长文档分块、批量提取、累计预算、失败恢复；规则/用例人工批准与版本冻结。
- **标准到执行**：账号准备与数据插件；页面观察、受约束测试计划、角色独立上下文；浏览器和 HTTP API 执行；未知副作用明确待核对；取消、租约、进程退出后恢复。
- **工程检查**：公共/已授权私有 GitHub 固定提交；Node test、pytest、Vitest、Jest、Playwright、ESLint、TypeScript、build；LCOV 原报告独立复核；受限 Node HTTP + 独立 PostgreSQL 临时部署与清理台账。
- **智能任务**：版本化能力目录、DAG 组合/发布、三个真实模板；目标建议批准后转为任务；有界只读探索；来源/版本/有效期受控记忆；基于证据的诊断，不改业务标准或测试结果。
- **交付决定**：缺陷分级依据、负责人、复测；全量统计和分页；证据保留与失效降级；幂等发布决定及快照；JSON/Markdown 导出。接受风险仍保留原 FAIL。
- **实际界面**：接入/上下文/设计/运行/准备/交付、模板、智能任务、部署、缺陷、发布评审。桌面与手机布局；无权限按钮禁用、API 再鉴权；错误保留非敏感输入、提交防重复。

## 明确边界与待补输入

1. GitHub App 的真实 ID/安装/仓库授权/回调/私钥文件与 webhook secret 需由部署方安全配置，随后验证私库下载和 Checks 回传。
2. 需完整且经业务批准的 PRD、第二真实项目、允许操作范围、独立角色账号引用，以及健康/隐蔽缺陷/修复的固定构建。试点工具已完成，资料缺失不能用合成样例填充。
3. 新增长文档跨块语义、目标规划需要真实模型评测，保留输入/用量/首败，人工复核语义。字面冲突识别不宣称穷尽自由表述冲突。
4. 探索为限定路径的无脚本只读观察；临时 Node 部署健康检查不等于完整业务验收；运行器需受信任主机与 Docker 28+，当前 Node 安装仅支持 npm 锁文件。
5. 本地 ARM64 镜像已按记录验证；镜像 registry 分发、其他架构、生产规模容量/SLA 不在本轮实测结论中。不存在“任意 Git 仓库输入后自动保证业务正确”的承诺。
