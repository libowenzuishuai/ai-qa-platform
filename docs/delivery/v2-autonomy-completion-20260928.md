# 网站自主能力、交互和复现工具交付

实施：2026-09-28—29。基线 `bbf45f9`，分支 `v2/autonomous-qa`。本文件更新上一轮网站自主交付的代码缺口说明；历史测试数字仍保留在原文件。

## 当前结论

这一轮把上一轮列出的探索、文件交互、人工认证接续、模型路由、离线调试、补充证据调查和隔离复现缩减接入了现有产品。新功能有真实 Chromium、临时 PostgreSQL、Python HTTP 和隔离夹具验证。模型决策由显式测试替身提供，本轮没有付费模型调用。

仍是开发预览。支持范围以本文的具体接口为准：不能把可执行代码、合成测试通过或模型兼容协议等同于任意网站质量、任意供应商兼容或完整 PRD 2.0 已验收。

## 新增的可用能力

### 1. 根据目标探索页面

网站配置支持“根据目标探索”。可以不预先列举操作顺序，改为批准角色、动作类型和输入数据集合。每轮重新观察页面元素、页面文字及已完成历史，Python 规划器选择当前真实元素；宿主分配动作 ID、检查授权并执行。

- 允许动态提议 click/fill/select/reload/wait；填写或选择只能引用批准的数据 ID，不能自行生成或取用凭据。
- 动态目标必须来自本轮观察，并属于批准角色。页面内容作为不可信数据传给模型。
- 状态未变却重复同一动作会停止；仍有轮数、时间、调用和 token 上限。
- 模型 done 仅表示探索结束；最终通过仍由冻结 Oracle 和独立读取节点决定。
- 有明确写接口授权才能发送写请求。授权 URL 不会自动授予创建、删除等任意权限。

### 2. 更多浏览器动作与文件证据

新增 hover/check/uncheck/press/scroll/upload/download。

- 按键限 Enter/Tab/Escape/方向键/Space；滚动限上下，不接受任意脚本。
- 上传引用同项目证据 ID，宿主检查文件有效期、哈希、大小及文件名。最多 8 MiB，不接受本机任意路径。
- 下载需批准精确文件名与大小上限；意外下载取消，下载字节登记为受限证据并计算 SHA-256。
- `platform.browser-read@1.1.0` 可以读取下载动作的文件哈希，绑定到独立断言。原 1.0.0 清单和执行仍保留，已发布组合不静默改变 Schema。
- 临时截图和下载文件在证据入库后清除，避免形成无台账的副本。
- 控制台 warning/error 进入运行证据。它们是调查线索，不能单独判定业务失败。

### 3. 人工认证后继续原浏览器

配置交互认证指示器后，登录流程可进入 WAITING_AUTH。运行器维持同一 BrowserContext 和租约，页面显示认证待办；用户在运行器可见浏览器完成验证后点击确认，运行器重新验证真实登录成功标识再继续。

- 运行器需设置 `AIQA_BROWSER_HEADFUL=true`，并运行在有桌面的环境。
- 平台不收集 OTP；“我已完成”只记确认，不直接认定登录成功。
- nonce、时限和活跃租约必须匹配；过期确认拒绝。
- 浏览器进程丢失后报 AUTH_BROWSER_LOST，不重放未知写入。
- 这是本地可见浏览器接续，不提供远程桌面或云端验证码代答。真实外部 MFA 服务尚未评测。

### 4. 决策/视觉配置固定与兼容通道

Profile 可固定 decision/vision 的 provider 与 model。新增模型组合发布时必须提供需要的 pin；执行前和实际配置比对，配置漂移则在发请求前拒绝。

- 文本生成沿用 `AIQA_TEXT_*`；视觉使用 `AIQA_VISION_*`。
- 决策可使用 `AIQA_DECISION_PROVIDER/BASE_URL/MODEL/API_KEY`。未配置独立 DECISION provider 时沿用 TEXT，仍受 pin 检查。
- provider 支持 `moonshot` 与显式 `openai-compatible`。后者要求兼容当前 Chat Completions JSON 请求形状；不是任意协议适配承诺。
- 只有 moonshot 的指定 Kimi 模型才发送其专属参数。
- 旧 Profile 维持兼容；尚未把所有 v1 文档生成作业升级为 Profile pin。pin 固定配置名，不能保证供应商背后的权重永远不变。

### 5. 历史回放中的节点调试和故障注入

停止的会话可以选择节点查看历史执行，并注入 TIMEOUT、DEPENDENCY_UNAVAILABLE、MODEL_OUTPUT_INVALID。注入每节点首个调用一次，其他调用只读取经校验的历史回执。它不访问目标，不调用模型，不更改原始结果。

这用于检查图的失败分支、重试与停止行为。缺少对应重试回执时明确失败；它不会创建新的真实输出。单节点视图仍先计算历史依赖，不能当作隔离运行当前网站的调试。

### 6. 关联代码差异和服务日志

缺陷调查接受同项目、同构建的补充 JSON 证据；验证所有权、哈希、大小和结构后关联 changedSymbols 与 stack，生成支持证据列表。

证据格式：`kind` 为 `code_diff` / `service_log` / `auth_log`，必填 `buildId`；可含 `requestId`、`changedSymbols: string[]`、`stack: string[]`、`message`。字段以接口 Schema 为准。调查仍为开放假设，不把符号命中宣称为已证明根因。

### 7. 隔离复现缩减及资源清理

组合页可由管理员安装、授权 `platform.reproduction-minimize@1.0.0`，再将其加入 Profile 和图。通过固定夹具协议重置隔离数据，逐步删减原步骤，在相同构建、Oracle、失败指纹下核对复现结果。

- 只访问批准环境的固定 reset/trial/cleanup 路径；不执行上传脚本或任意命令。
- 每次尝试独立命名空间；每次外部调用前落意图，返回后落回执。工具与资源预算逐次扣记，撤权/取消/构建漂移及时停止。
- 100 步、30 次试验上限；目标为有界 **1-minimal**（不能再删一个步骤），不宣称全局最短。
- 重置失败、身份不一致、无证据或清理未确认均不能成为 verified 结果。
- 资源页从有校验的意图/回执重建台账；缺证据显示 unknown。失败清理保留残留，由管理员对原命名空间重试，不能输入新的清理 URL 或任意资源名。
- 重试清理只允许停止且不持有活跃租约的会话；使用原始调用输入、固定端点和幂等键。原业务失败不被清理成功覆盖。

**适配边界**：目标需要实现可信夹具服务，实际执行隔离、重置和冻结断言。平台不凭空推断任意站点的数据重置规则。协议及样例见 [复现适配器指南](../v2-reproduction-adapter.md)。

## 入口

- 智能测试 → 配置网站自主测试：探索开关、批准数据、模型 pin、文件动作。
- 智能测试 → 组合编辑：启用隔离复现能力。
- 会话详情：人工认证、资源台账/清理、历史节点调试及故障注入。
- 缺陷详情：补充证据 ID、重新调查。

新增 API：

- `POST /api/v2/sessions/:id/auth-complete`
- `GET /api/v2/sessions/:id/resources`
- `POST /api/v2/sessions/:id/resources/:key/cleanup`

现有 replay/investigate/browser-blueprints/能力目录接口扩展。无需数据库迁移。
